# Scrum Master assessment (written before reading the others)

1. **Already efficient.** Contracts or posted Stable commits before parallel work keep seams at 1 per Sprint. Peer review by a second Developer found real defects every Sprint. One Sprint PR with full checks once is cheaper than per-story CI.
2. **Inefficient.** (a) Fixed fan-out: I spawned 5 Developers every Sprint because 5 was the cap, not because the work needed 5. (b) Cold start: every Developer pays ~90k tokens to load the brief, Sprint doc, requirements and code before writing a line; the pitch round cost ~460k for nine one-line ideas. (c) Fix-up resumes re-enter a 150–250k transcript to change a few lines; I or a fresh small agent could do them for a fraction. (d) My own context is swamped by GitHub notification boilerplate and full Developer reports. (e) The shared brief grows every retro and every Developer reads all of it.
3. **Wrong assumptions in the proposal.** "Lead + 4–5 for complex work" assumes parallelism is the speed lever; our real limiter is the 5-hour usage window, which stopped the team in four of seven Sprints. More agents in parallel hit the limit sooner. Also, the proposal assumes the lead can review everything; my own reviews missed things peer reviewers caught (privacy wording, °F).
4. **Underused.** Model routing (all Developers ran on the most capable model, including pitches and doc edits). Reasoning effort per task. Graphify answers being shared: each Developer re-queried the same callers. The code-review skill at low effort before peer review.
5. **What the stakeholder may not know.** Resuming a background agent replays its whole transcript, so "keep the same Developer for the fix-up" is expensive; and it only works while its worktree exists. A fresh agent with a 1-page spec is often cheaper than a resume. Prompt caching makes a shared, stable brief prefix cheap to re-read, but only if it doesn't change mid-Sprint.
6. **Risks.** One lead doing PO, SM, architect and QA removes the only independent check on the lead's own decisions (Sprint 4's duplicate was caused by my brief). Keep an independent reviewer for anything the lead writes.
7. **Change.** Size the team per Sprint from the work, default 2–3; route by model; replace the long brief with a 1-page task spec plus a short stable rules file; do small fix-ups in the lead; keep peer review; keep interaction logs but one line per event; measure tokens per merged story.
